## Q3 [PASS] (factual)

**Q:** What is model distillation?

**A:** Model distillation, also called knowledge distillation, is a method in which a small model (called the student) is trained to mimic a larger model (called the teacher). The knowledge of the big model is distilled into the small model, hence the term distillation.

Traditionally, the goal is to produce smaller models for deployment, since deploying a big model can be resource-intensive. This process can produce a smaller, faster student model that retains performance comparable to the teacher. For example, DistilBERT reduces the size of a BERT model by 40% while retaining 97% of its language comprehension capabilities and being 60% faster. Similarly, Alpaca was created by finetuning a 7-billion-parameter model on examples generated by a 175-billion-parameter model, resulting in similar behavior while being only 4% the size of the teacher model.

The student model can either be trained from scratch or finetuned from a pre-trained model. It's worth noting that not all models can be distilled, as many model licenses prohibit using their outputs to train other models, particularly competing ones.

The goal is to capture the larger model's knowledge and behaviors in a smaller model with fewer parameters. For example, DistilBERT reduced BERT's size by 40% while retaining 97% of its capabilities, and Alpaca was created by finetuning a 7-billion-parameter model to behave like a 175-billion-parameter model.

In summary, quantization reduces precision to save memory, while distillation creates an entirely smaller model that replicates a larger model's behavior.

**Q:** What is RAG?

**A:** RAG stands for retrieval-augmented generation. It is a technique that enhances a model's generation capabilities by retrieving relevant information from external memory sources before generating a response. These external sources can include internal databases, previous chat sessions, or the internet.

RAG works by following a retrieve-then-generate pattern: first, the system retrieves the most relevant information for a given query from external sources, and then the model uses this retrieved information to generate an answer. This approach is particularly useful for knowledge-intensive tasks where all available knowledge cannot be directly input into the model at once.

The key benefit of RAG is that it provides models with specific, relevant context for each query, which helps them generate more detailed and accurate responses while reducing hallucinations (incorrect or fabricated information). It's a prompt-based method that influences the model's quality through inputs without modifying the model itself.

## Q8 [PASS] (factual)

**Q:** What are embeddings?

**A:** Embeddings are numerical representations that aim to capture the meaning of original data. Since computers work with numbers, models need to convert their input into numerical representations that computers can process.

An embedding is a vector - for example, the sentence "the cat sits on a mat" might be represented as an embedding vector like [0.11, 0.02, 0.54]. In practice, embedding vectors typically contain between 100 and 10,000 elements.

Embeddings are considered representations of complex data in a lower-dimensional space. For instance, while a 10,000-element vector space may seem high-dimensional, it's much lower than the dimensionality of the raw data it represents.

Various models are trained specifically to produce embeddings, including open source models like BERT, CLIP (Contrastive Language–Image Pre-training), and Sentence Transformers, as well as proprietary embedding models available through APIs. Different models produce embeddings of varying sizes - for example, Google's BERT base produces 768-dimensional embeddings, while OpenAI's text-embedding-3-large produces 3072-dimensional embeddings.

## Q11 [PASS] (factual)

**Q:** What is backward propagation?

**A:** Backward propagation (or backpropagation) is the process of updating a model's weights using the aggregated signals from the forward pass during neural network training. 

It works through the following steps:

1. **Calculate the loss**: Compare the computed output from the forward pass against the expected output (ground truth). The difference between them is called the loss.

2. **Compute gradients**: Calculate how much each trainable parameter contributes to the mistake by taking the derivative of the loss with respect to each trainable parameter. This value is called the gradient - there's one gradient value per trainable parameter. Parameters with high gradients significantly contribute to the loss and should be adjusted more.

3. **Adjust parameters**: Update trainable parameter values using their corresponding gradients. The amount of adjustment is determined by an optimizer (such as SGD or Adam).

During training, both the forward pass (computing output from input) and backward pass are executed, while during inference, only the forward pass is needed.

## Write Clear and Explicit Instructions

**Be specific and unambiguous**: Clearly explain what you want the model to do. For example, if scoring an essay, specify whether the scale is 1-5 or 1-10, and whether fractional scores are acceptable or only integers should be used.

Ask the model to slow down and think step by step, which can yield surprising improvements in responses.

**Separate prompts from code**: Store prompts in separate files (like prompts.py) and reference them in your application code. This approach offers several advantages:
- **Reusability**: Multiple applications can use the same prompt
- **Testing**: Code and prompts can be tested separately
- **Readability**: Both code and prompts are easier to read when separated

**Version your prompts**: Track changes to prompts over time for better management and debugging.

## Keep It Simple

Start by writing your own prompts without tools to better understand the underlying model and your requirements. If using prompt engineering tools, always inspect the prompts they produce and track API calls.

## Consider Model-Specific Quirks

While these general practices work across models, each model may have specific quirks that respond to particular prompt tricks, so consult model-specific guides when available.

**Q:** What is the difference between data-centric AI and model-centric AI?

**A:** The difference between data-centric AI and model-centric AI lies in their approach to improving AI performance:

**Model-centric AI** focuses on enhancing the models themselves to improve AI performance. This involves designing new architectures, increasing the sizes of the models, or developing new training techniques.

**Data-centric AI** focuses on enhancing the data to improve AI performance. This involves developing new data processing techniques and creating high-quality datasets that allow better models to be trained with fewer resources.

In practice, model-centric approaches typically involve keeping the dataset constant while trying to train the best possible model (as was common in early deep learning benchmarks like ImageNet). Data-centric approaches, on the other hand, keep the model constant while trying to develop the best dataset through techniques such as fixing incorrect labels, adding edge case examples, and augmenting data.

While this division helps guide research, meaningful technological progress often requires investment in both model and data improvements.

**Q:** How does entropy and cross-entropy relate?

**A:** Entropy and cross-entropy are closely related concepts that both measure predictability, but they differ in an important way:

**Entropy** measures how much information a token carries in a language or dataset. It reflects the inherent predictability of the data itself - the lower the entropy, the more predictable the language is.

**Cross-entropy** measures how difficult it is for a language model to predict what comes next in a dataset. It depends on two factors:

1. The training data's predictability (measured by the data's entropy)
2. How much the distribution learned by the language model diverges from the true distribution of the training data

Mathematically, if P represents the true distribution of the training data and Q represents the distribution learned by the language model, then:
- The training data's entropy is H(P)
- The cross-entropy incorporates both the entropy H(P) and the divergence between the model's distribution and the true distribution (measured by KL divergence)

In essence, cross-entropy extends the concept of entropy by accounting for the difference between what the model has learned versus the actual data distribution. Both metrics share the same mathematical notation (H) and are measured in the same units (bits or nats).
