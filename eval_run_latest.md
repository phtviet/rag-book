**Q:** What is quantization?

**A:** Quantization refers to the practice of converting a model from a format with more bits to a format with fewer bits. It is a straightforward and efficient way to reduce a model's memory footprint. For example, for a model of 13 billion parameters, using FP32 means 4 bytes per weight or 52 GB for the whole weights. If you can reduce each value to only 2 bytes, the memory needed for the model's weights decreases to 26 GB.

Strictly speaking, it's quantization only if the target format is integer. However, in practice, quantization is used to refer to all techniques that convert values to a lower-precision format. Reducing precision, also known as quantization, is a cheap and extremely effective way to reduce a model's memory footprint. It's straightforward to do and generalizes over tasks and architectures. In the context of ML, low precision generally refers to any format with fewer bits than the standard FP32.

**Q:** What is model distillation?

**A:** Model distillation (also called knowledge distillation) is a method in which a small model (student) is trained to mimic a larger model (teacher). The knowledge of the big model is distilled into the small model, hence the term distillation.

Traditionally, the goal of model distillation is to produce smaller models for deployment. Deploying a big model can be resource-intensive. Distillation can produce a smaller, faster student model that retains performance comparable to the teacher. For example, DistilBERT, a model distilled from BERT, reduces the size of a BERT model by 40% while retaining 97% of its language comprehension capabilities and being 60% faster.

The student model can be trained from scratch like DistilBERT or finetuned from a pre-trained model like Alpaca. In 2023, Taori et al. finetuned Llama-7B, the 7-billion-parameter version of Llama, on examples generated by text-davinci-003, a 175-billion-parameter model. The resulting model, Alpaca, behaves similarly to text-davinci-003, while being 4% the size of the teacher model.

## Q7 [PASS] (factual)

**Q:** What is RAG?

**A:** RAG, or retrieval-augmented generation, is a technique that enhances a model's generation by retrieving relevant information from external memory sources. An external memory source can be an internal database, a user's previous chat sessions, or the internet.

The retrieve-then-generate pattern underlying RAG was first introduced in "Reading Wikipedia to Answer Open-Domain Questions" (Chen et al., 2017). In this approach, the system first retrieves relevant information (such as five Wikipedia pages most relevant to a question), then a model uses or reads the information from these sources to generate an answer.

The term retrieval-augmented generation was coined in "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks" (Lewis et al., 2020). The paper proposed RAG as a solution for knowledge-intensive tasks where all the available knowledge can't be input into the model directly. With RAG, only the information most relevant to the query, as determined by the retriever, is retrieved and input into the model. Lewis et al. found that having access to relevant information can help the model generate more detailed responses while reducing hallucinations.

RAG is a prompt-based method, as it influences the model's quality solely through inputs without modifying the model itself. It is one of two dominating patterns for context construction, the other being the agentic pattern.

## Q8 [PASS] (factual)

**Q:** What are embeddings?

**A:** Embeddings are numerical representations in the form of vectors that aim to capture the meaning of the original data. Since computers work with numbers, models need to convert their input into numerical representations that computers can process.

An embedding is a vector - for example, the sentence "the cat sits on a mat" might be represented using an embedding vector like [0.11, 0.02, 0.54]. In reality, the size of an embedding vector (the number of elements in the embedding vector) is typically between 100 and 10,000.

An embedding is considered a representation of complex data in a lower-dimensional space. For instance, while a 10,000-element vector space seems high-dimensional, it's much lower than the dimensionality of the raw data.

Models trained especially to produce embeddings include open source models like BERT, CLIP (Contrastive Language–Image Pre-training), and Sentence Transformers. There are also proprietary embedding models provided as APIs. Common embedding sizes include Google's BERT (768 for base, 1024 for large), OpenAI's CLIP (512 for both image and text), OpenAI Embeddings API (1536 for text-embedding-3-small, 3072 for text-embedding-3-large), and Cohere's Embed v3 (1024 for embed-english-v3.0, 384 for embed-english-light-3.0).

Many ML models, including GPTs and Llamas, involve a step to generate embeddings as models typically require their inputs to first be transformed into vector representations.

  - Continuous batching

## Q11 [PASS] (factual)

**Q:** What is backward propagation?

**A:** Backward propagation (backpropagation) is the process of updating a model's weights using the aggregated signals from the forward pass during neural network training. 

The backward pass works as follows:

1. Compare the computed output from the forward pass against the expected output (ground truth). If they are different, the model made a mistake, and the parameters need to be adjusted. The difference between the computed output and the expected output is called the loss.

2. Compute how much each trainable parameter contributes to the mistake. This value is called the gradient. Mathematically, gradients are computed by taking the derivative of the loss with respect to each trainable parameter. There's one gradient value per trainable parameter. If a parameter has a high gradient, it significantly contributes to the loss and should be adjusted more.

3. Adjust trainable parameter values using their corresponding gradient. How much each parameter should be readjusted, given its gradient value, is determined by the optimizer. Common optimizers include SGD (stochastic gradient descent) and Adam. For transformer-based models, Adam is the most widely used optimizer.

During training, each training step consists of two phases: the forward pass (computing the output from the input) and the backward pass (updating the model's weights). During inference, only the forward pass is executed.

**Q:** What are the best practices of prompt engineering?

**A:** The best practices for prompt engineering include:

**Write Clear and Explicit Instructions**
- Explain without ambiguity what you want the model to do
- If you want the model to score an essay, explain the score system (e.g., 1 to 5 or 1 to 10)
- Specify how to handle uncertainty (e.g., pick a score to the best of its ability or output "I don't know")
- As you experiment, adjust prompts to prevent undesirable behaviors (e.g., if the model outputs fractional scores like 4.5 and you don't want them, update your prompt to specify only integer scores)
- Provide examples and relevant information
- Ask the model to slow down and think step by step, which can yield surprising improvements

**Organize and Version Prompts**
- Separate prompts from code (e.g., put prompts in a file like prompts.py and reference them when creating model queries)
- This approach provides several advantages:
  - **Reusability**: Multiple applications can reuse the same prompt
  - **Testing**: Code and prompts can be tested separately (e.g., code can be tested with different prompts)
  - **Readability**: Separating prompts from code makes both easier to read

**Keep It Simple**
- Start by writing your own prompts without any tool to gain better understanding of the underlying model and your requirements
- If using a prompt engineering tool, always inspect the prompts it produces to verify they make sense and track how many API calls it generates

**Consider Model Quirks and Biases**
- AI models have their quirks and biases that need to be considered for a productive relationship with them
- Each model likely has its own quirks that respond to specific prompt tricks, so look for prompt engineering guides specific to the model you're working with

**Q:** What are the malicious attacks that can be done with prompt engineering?

**A:** Prompt engineering can be exploited through three main types of malicious attacks:

1. **Prompt extraction**: Extracting the application's prompt, including the system prompt, either to replicate or exploit the application.

2. **Jailbreaking and prompt injection**: Getting the model to do bad things. This includes:
   - **Direct prompt injection**: Placing malicious instructions directly in the prompt
   - **Indirect prompt injection**: A more powerful attack where attackers place malicious instructions in tools that the model is integrated with, rather than in the prompt directly. This can take forms such as:
     - **Passive phishing**: Attackers leave malicious payloads in public spaces like web pages, GitHub repositories, YouTube videos, and Reddit comments, waiting for models to find them via tools like web search. For example, an attacker could insert code to install malware into a public GitHub repository, which an AI model might discover and suggest importing, leading to unknowing execution of the malware.

3. **Information extraction**: Getting the model to reveal its training data or information used in its context.

These attacks pose multiple risks:

- **Remote code or tool execution**: Bad actors can invoke unauthorized code or tool execution, such as executing SQL queries that reveal sensitive user data, sending unauthorized emails, or generating malicious code to compromise systems.

- **Data leaks**: Bad actors can extract private information about the system and users.

- **Social harms**: AI models can help attackers gain knowledge and tutorials about dangerous or criminal activities, such as making weapons, evading taxes, and exfiltrating personal information.

- **Misinformation**: Attackers might manipulate models to output misinformation to support their agenda.

- **Service interruption and subversion**: This includes giving access to unauthorized users, giving high scores to bad submissions, rejecting applications that should be approved, or causing the model to refuse to answer questions.

- **Brand risk**: Politically incorrect and toxic statements can cause PR crises and damage reputation.

**A:** The future of comparative evaluation has several key aspects:

**Benefits that ensure its continued relevance:**

1. **Easier for human evaluators**: As models become stronger and surpass human performance, it may become impossible for human evaluators to give model responses concrete scores. 3. **Never gets saturated**: Unlike benchmarks that become useless when model performance achieves perfect scores, comparative evaluations will never get saturated as long as newer, stronger models are introduced.

**Role in evaluation frameworks:**

Comparative evaluation can give discriminating signals about models that can't be obtained otherwise. For offline evaluation, it can be a great addition to evaluation benchmarks. For online evaluation, it can be complementary to A/B testing.

**Q:** When should we finetune a model?

**A:** Finetuning should be attempted in the following situations:

**After extensive experiments with prompt-based methods**: Finetuning is generally attempted after extensive experiments with prompt-based methods, as it requires significantly more resources in data, hardware, and ML talent compared to prompting.

**To improve model quality**: The primary reason for finetuning is to improve a model's quality in terms of both general capabilities and task-specific capabilities.

**When a general-purpose model underperforms on your specific task**: If a model that performs well on a wide range of benchmarks doesn't perform well on your specific task, or if the model wasn't sufficiently trained on your task, finetuning it with your data can be especially useful.

**For specific format generation**: Finetuning is commonly used to improve a model's ability to generate outputs following specific structures, such as JSON or YAML formats.

**For specialized domains or dialects**: When an out-of-the-box model works well on standard tasks but fails on less common variants (for example, a model good at converting text to standard SQL but failing with a less common SQL dialect, or working well on standard SQL for common queries but failing for customer-specific queries), finetuning on data containing these specific variants will help.

**When you have the necessary resources and infrastructure**: Finetuning should only be considered when you have annotated data, knowledge of how to train models, the ability to serve the finetuned model, and a policy and budget for monitoring, maintaining, and updating the model.

**Not as a first step**: If you're just starting to experiment with a project, finetuning is rarely the first thing you should attempt due to its high up-front investments and continual maintenance requirements.

## Q20 [PASS] (synthesis)

**Q:** How does entropy and cross-entropy relate?

**A:** Entropy and cross-entropy are closely related concepts that both measure predictability, but they differ in what they measure:

**Entropy** measures how much information, on average, a token carries in a language or dataset. It measures the inherent predictability of the training data itself. The lower a language's entropy (the less information a token carries), the more predictable that language is.

**Cross-entropy** measures how difficult it is for a language model to predict what comes next in a dataset. A model's cross-entropy on training data depends on two qualities:

1. The training data's predictability, measured by the training data's entropy
2. How the distribution captured by the language model diverges from the true distribution of the training data

Mathematically, if P is the true distribution of the training data and Q is the distribution learned by the language model:
- The training data's entropy is H(P)
- The divergence of Q with respect to P is measured using Kullback-Leibler (KL) divergence, represented as DKL(P || Q)

In essence, entropy measures the inherent unpredictability of the data itself, while cross-entropy measures how well a model can predict that data. Cross-entropy incorporates both the data's entropy and the model's divergence from the true data distribution.
